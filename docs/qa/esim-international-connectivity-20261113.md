## Evidence and test limits

- The signed local Telna agreement (`Complete_with_Docusign_Chatforia_-_Telna_-_G.pdf`, pages 29–33) covers profile provisioning and says service depends on an agreed destination/operator list. Its Annex 1 table is blank; it does not define Unlimited speed thresholds, reset periods, or an APN value. The draft agreement was not used to infer production terms.
- The Telna adapter sends `POST /v2.1/pcr/packages` with the existing ICCID and configured `package_template`, and polls package usage by returned package ID. This supports the application flow, but a live account or Telna response is needed to prove cross-template reuse and package coexistence.
- Web focused tests: 23 passed; web production build passed. Voice mount regression test: 1 passed. Three mocked server suites passed 95 tests with an isolated no-database Jest configuration; the Telna adapter suite needed its stale relative mock paths fixed before it would load. iOS simulator build and six focused `WirelessServiceTests` passed; Android offline debug build and `testDebugUnitTest` passed. Database-backed server Jest suites could not run: their standard setup requires a dedicated migrated `TEST_DATABASE_URL`; an attempt to initialize a disposable local PostgreSQL cluster failed because the host could not allocate PostgreSQL shared memory. The added Stripe billing integration case remains unexecuted here.
- Automated tests establish route selection, status serialization and UI rendering where run. They do not establish radio attachment, Telna package policy, Twilio console configuration, APNs/FCM delivery, or PSTN/SMS routing in a foreign country.

## Questions to send to Telna before launch approval

1. Can one installed ICCID accept each of Chatforia's Local, Europe, Global, and Unlimited template IDs over successive purchases and while older packages remain active? What is the exact precedence and expiry behavior for concurrent packages, including `NOT_ACTIVE` top-ups?
2. Supply the production package template IDs and, for each, its validity start/reset, high-speed allowance, reduced speed, traffic-policy identifier, and any PCR `active_throttling` interaction. Does a SIM-level `NO_LIMIT` write bypass package throttling?
3. Supply the account-specific destination/PLMN list, per-template network whitelist, billing group, automatic network-selection and roaming configuration, and the APN value or confirmation that it is auto-configured.
4. Confirm whether moving an eSIM to another device requires a new ICCID, whether multiple packages on the old ICCID must be transferred independently, and the provider's safe cleanup/reconciliation procedure after an uncertain package-create result.
