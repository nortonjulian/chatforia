## Evidence and test limits

- The signed local Telna agreement (`Complete_with_Docusign_Chatforia_-_Telna_-_G.pdf`, pages 29–33) covers profile provisioning and says service depends on an agreed destination/operator list. Its Annex 1 table is blank; it does not define Unlimited speed thresholds, reset periods, or an APN value. The draft agreement was not used to infer production terms.
- The Telna adapter sends `POST /v2.1/pcr/packages` with the existing ICCID and configured `package_template`, and polls package usage by returned package ID. This supports the application flow, but a live account or Telna response is needed to prove cross-template reuse and package coexistence.
- The five relevant server suites passed **108 tests** under the repository's Jest configuration against a new disposable PostgreSQL 18 container with all 164 repository migrations applied. This includes the Stripe billing integration case, real-PostgreSQL replacement integration (with a fake Telna provider), Telna adapter mocks, wireless routes, and replacement service tests. No production database or live provider was used.
- Web focused tests: 23 passed; web production build passed. Voice mount regression test: 1 passed. iOS simulator build and six focused `WirelessServiceTests` passed; Android offline debug build and `testDebugUnitTest` passed.
- Restored only lockfile-pinned ESLint plugins and the macOS Sharp runtime in a temporary verification dependency tree; the repository lockfile was unchanged. Full ESLint runs but reports 383 errors and 2,621 warnings across the existing codebase. Changed connectivity files have no new lint errors. The sole error in a changed file, `react-refresh/only-export-components` at `client/src/pages/UpgradePlan.jsx:103`, is identical on the pre-project base commit. The full-repo lint gate remains blocked by pre-existing findings outside this project.
- Automated tests establish route selection, status serialization and UI rendering where run. They do not establish radio attachment, Telna package policy, Twilio console configuration, APNs/FCM delivery, or PSTN/SMS routing in a foreign country.

## Consolidated Telna confirmation checklist

Request written answers for Chatforia's **production account and exact package template IDs**, with a current configuration export or documented API response where possible. The signed agreement does not supply these values.

- [ ] **One installed ICCID:** Can the same downloaded profile accept subsequent Local, Europe, Global, and Unlimited purchases without a second eSIM installation? Is reuse allowed after expiry and across billing groups or inventory assignments? Identify template or profile-state exceptions.
- [ ] **Multiple packages:** Can two or more packages coexist on one ICCID? Define `ACTIVE` and `NOT_ACTIVE`, priority/activation order, destination changes, automatic activation, validity start, expiry while queued, termination behavior, and whether remaining balances stay independently scoped to each package ID. Provide expected API responses for an active pack plus a queued top-up.
- [ ] **Networks and setup:** Supply the account-specific destination/PLMN list and per-template network whitelist, roaming defaults, automatic-selection behavior, any required manual network selection, and the APN value or written confirmation that it is auto-configured. Identify destination exclusions and billing-group differences.
- [ ] **Unlimited policy:** For every Unlimited template, supply the high-speed allowance, reduced speed, measurement/reset period, traffic-policy ID, and the expected package usage response when local `totalDataMb`/`remainingDataMb` are zero. Confirm whether PCR `active_throttling: NO_LIMIT` on suspend/resume bypasses or changes package throttling. Any policy change requires approval.
- [ ] **Replacement ICCID:** Confirm that a new ICCID/profile is required for device transfer, when the new profile becomes usable, and how remaining data and original expiry must be preserved if the provider issues a larger or longer-lived package. Define old-package termination, old-SIM suspension, handling of other packages on the old ICCID, and reconciliation after an uncertain package-create result.

## Remaining code or automated-testing decisions

- `GET /api/wireless/status` inspects the ten newest unexpired pack candidates. An eleventh older `ACTIVE` package would be missed if ten newer packages were `NOT_ACTIVE`. Removing the cap would increase Telna polling on every status request; choose a provider-supported active-package lookup or an explicit pagination/rate-limit strategy before changing this behavior.
- Free Chatforia number HOLD policy is based on outbound activity. Whether inbound-only use should protect a number is a product policy decision; the international routing code does not change the policy.
- Older non-English product strings can still contain the superseded speed/coverage wording. Review them with the ongoing localization QA rather than mass-replacing translations in this engineering branch.
